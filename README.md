# CPP Module 07 — テンプレート（Templates）

このモジュールのテーマは **テンプレート（templates）** です。
C++ の「ジェネリックプログラミング（generic programming）」を支える、
とても重要な仕組みを学びます。

このREADMEでは、まず **「テンプレートとは何か」** を初学者向けに丁寧に説明し、
そのあと各演習（ex00 / ex01 / ex02）の概要と、全体のビルド方法をまとめます。
各演習の詳しい解説は、それぞれのフォルダの `README.md` にあります。

## 1. テンプレートとは何か

### 1-1. 「同じことを型ごとに書きたくない」問題

たとえば「2つの値を入れ替える `swap` 関数」を考えます。
テンプレートを知らないと、型ごとに同じ中身を何度も書くことになります。

```cpp
void swap(int& a, int& b)         { int tmp = a; a = b; b = tmp; }
void swap(double& a, double& b)   { double tmp = a; a = b; b = tmp; }
void swap(std::string& a, std::string& b) { std::string tmp = a; a = b; b = tmp; }
// ... char, float, 自作クラス ... と無限に増える
```

中身（ロジック）は全部同じなのに、**型が違うだけ**で関数を量産しています。
これは面倒だし、バグの温床です。

### 1-2. テンプレート＝「型を後で決める設計図」

テンプレートを使うと、「型」を **後から差し込める穴（パラメータ）** にできます。

```cpp
template <typename T>   // ← T という「型の名前」を1つ受け取る設計図
void swap(T& a, T& b)
{
	T tmp = a;
	a = b;
	b = tmp;
}
```

- `template <typename T>` は「これから書くものは、型 `T` をパラメータに持つ
  **設計図（テンプレート）** です」という宣言。
- `T` は仮の型名。`int` でも `std::string` でも、`swap` を使うときに決まります。
- `typename` の代わりに `class` と書いてもまったく同じ意味です
  （`template <class T>`）。本モジュールでは `typename` を使います。

これが **ジェネリックプログラミング（generic programming）** です。
「特定の型に縛られない、汎用的なコード」を1回書けば、あらゆる型で使い回せます。

### 1-3. 型推論（template argument deduction）

テンプレート関数を呼ぶとき、多くの場合 `T` が何かを **書かなくても**、
コンパイラが引数から自動的に推論してくれます。これを **型推論** と呼びます。

```cpp
int a = 1, b = 2;
swap(a, b);          // 引数が int → コンパイラが T = int と推論
                     // swap<int> を呼んだのと同じ

std::string s = "x", t = "y";
swap(s, t);          // 引数が std::string → T = std::string と推論
```

明示的に型を指定したいときは `swap<int>(a, b)` のように `< >` で書けます
（ex01 で `printElem<int>` のように使います）。

### 1-4. インスタンス化（instantiation）— 「設計図から実体が作られる」

ここがテンプレートの **最重要ポイント** です。

テンプレートは **それ自体ではコード（機械語）になりません**。
あくまで「設計図」です。コンパイラは、テンプレートが **実際に使われた瞬間** に、
「その型用の本物の関数／クラス」を生成します。これを **インスタンス化** と呼びます。

```cpp
swap(a, b);   // ここで初めて T=int 版の swap が "生成" される（インスタンス化）
```

- `swap<int>` を1度も使わなければ、`swap<int>` のコードは1バイトも生成されません。
- `swap<int>` と `swap<std::string>` を使えば、**2種類**の関数が生成されます。

### 1-5. なぜテンプレートは「ヘッダ」に書くのか（最重要）

普通の（テンプレートでない）関数は、こう分けて書きます。

```
foo.hpp : 宣言（プロトタイプ）  void foo(int);
foo.cpp : 定義（実装）          void foo(int) { ... }
```

これは、`foo.cpp` を一度コンパイルすれば `foo` の機械語ができ、
他の `.cpp` はリンク時にそれを共有できるからです。

**テンプレートはこれができません。** 理由は 1-4 のインスタンス化です。

コンパイラが `swap<int>` の本体を生成するには、`swap` の **中身（定義）が見えている**
必要があります。`main.cpp` が `swap(a, b)` を呼ぶ瞬間、`main.cpp` をコンパイルしている
コンパイラの目の前に `swap` の定義がなければ、`swap<int>` を生成できません。

もし定義を `swap.cpp` だけに隠してしまうと、`main.cpp` のコンパイル時には
「`swap` という設計図がある」ことしか分からず、`swap<int>` の実体が作れません。
そして `swap.cpp` 側も「誰が `swap<int>` を必要としているか」を知らないので、
やはり `swap<int>` を作りません。結果、リンク時に「`swap<int>` が見つからない」
というエラー（undefined reference）になります。

**→ だから、テンプレートの「定義」はヘッダに書き、使う側が `#include` する。**
こうすれば、`main.cpp` をコンパイルする時点で定義が見えるので、必要な型の実体を
その場で生成できます。

> 補足: 「通常の関数の実装をヘッダに書くのは禁止」というルールがありますが、
> テンプレートは **例外** です。理由は上記の通り、テンプレートは構造上ヘッダに
> 定義を置く必要があるからです（複数の `.cpp` から include されても、テンプレートは
> 多重定義エラーになりません。コンパイラ／リンカが同一の実体をまとめてくれます）。

### 1-6. `.tpp` ファイルとは

テンプレートの定義をヘッダに書くと、宣言と実装が混ざって読みづらくなることがあります。
そこで、慣習として **実装部分だけを `.tpp`（template implementation）という別ファイル**
に切り出し、ヘッダの末尾でそれを `#include` する書き方があります。

```cpp
// Array.hpp
template <typename T>
class Array { /* 宣言だけ */ };

#include "Array.tpp"   // ← ヘッダの一番下で実装を取り込む
```

```cpp
// Array.tpp
template <typename T>
Array<T>::Array() { /* 実装 */ }
```

- `.tpp` は **コンパイラにとってはただのテキスト**です。`#include` は中身を
  そのまま貼り付けるだけなので、結果的に「定義がヘッダ経由で見える」状態は変わりません。
- あくまで **人間の可読性のため** の分割です。本モジュールでは ex02 でこの形を使います。

### 1-7. 関数テンプレート vs クラステンプレート

| | 関数テンプレート | クラステンプレート |
|---|------------------|--------------------|
| 例 | `swap<T>`, `min<T>`, `iter<T,F>` | `Array<T>`, `std::vector<T>` |
| 型推論 | 引数から自動推論できる | 基本は明示が必要（`Array<int>` と書く） |
| 生成されるもの | 型ごとの関数 | 型ごとのクラス全体（全メンバ関数） |
| 本モジュール | ex00 / ex01 | ex02 |

- **関数テンプレート**: 関数を汎用化する。引数の型から `T` を推論できるのが便利。
- **クラステンプレート**: クラス全体を汎用化する。`std::vector<int>` のように
  `< >` で型を指定して使う。`Array<int>` も同じ仲間です。

## 2. 各演習の概要

### ex00 — whatever（関数テンプレート入門）
`swap` / `min` / `max` を関数テンプレートで実装します。
型推論、`::swap` と書く理由（`std::swap` との衝突回避）などを学びます。

### ex01 — iter（配列と「関数を渡す」）
配列の全要素に、渡された関数を適用する `iter` を実装します。

が学びどころです。

このモジュールの集大成で、**深いコピー（deep copy）**、`new T[n]()` による
デフォルト初期化、`operator[]` の境界チェックと例外を扱います。
→ 詳細は [`ex02/README.md`](./ex02/README.md)

## 3. 全体のビルド方法

各演習フォルダに `Makefile` があります。
共通の必須コンパイル条件は次の通りです（**警告ゼロ・エラーゼロ**）。

```
c++ -Wall -Wextra -Werror -std=c++98 *.cpp -o <name>
```

各フォルダで `make` するか、直接コンパイルできます。

```bash
# ex00
cd ex00 && make            # -> ./whatever が生成される
./whatever

# ex01
cd ex01 && make            # -> ./iter が生成される
./iter

# ex02
cd ex02 && make            # -> ./array が生成される
./array
```

Makefile の主なルール:

| ターゲット | 動作 |
|-----------|------|
| `make` / `make all` | 実行ファイルをビルド |
| `make clean` | オブジェクトファイル(`.o`)を削除 |
| `make fclean` | `.o` と実行ファイルを削除 |
| `make re` | `fclean` してから再ビルド |

ヘッダ（`.hpp` / `.tpp`）を変更したら `.o` も作り直すよう依存関係を設定しているため、
テンプレートの実装を直したのにビルドが古いまま、という事故は起きません。

## 4. 禁止事項（このモジュールで守るルール）

- **C++98 のみ**（`-std=c++98`）。C++11 以降の機能は使わない。
- 禁止: `printf` などの `*printf()`、`malloc` などの `*alloc()`、`free()`、
  `using namespace`、`friend`。
- STL コンテナ（`vector` 等）と `<algorithm>` は **使用禁止**
  （まさにその `vector` を自作するのが ex02 の趣旨）。
- メモリリーク厳禁（ex02 は `new[]` / `delete[]` を正しく対応させる）。

## 5. このモジュールで「言えるようになる」と良いこと（ピア評価用）

- テンプレートとは「型を後から決める設計図」であり、使われた型ごとに
  **インスタンス化**されてコードが生成される。
- だから、テンプレートの **定義はヘッダに書く必要がある**
  （使う側のコンパイル時に定義が見えていないと実体を作れないから）。
- `.tpp` は人間の可読性のための分割で、中身はヘッダに `#include` される。
- ex02 の **深いコピー** は、ポインタが指す中身まで丸ごと複製すること。
  浅いコピー（ポインタだけコピー）だと、二重解放やデータ破壊が起きる。
